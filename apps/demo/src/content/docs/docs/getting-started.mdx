OpenDIL renders a growing text response as an interactive React interface. Your application supplies the source; the document can contain Markdown, controls, charts, and its own state.

## Install

Use React 19.

```sh
npm install @snackbit/opendil react react-dom
```

For the default iframe isolation mode (`mode="isolated"`), also copy the runtime assets. The asset CLI requires Node 22 or newer:

```sh
npx opendil copy-assets --out public/opendil
```

Serve the copied `opendil` directory with your application. The iframe renderer loads its sandboxed frame from `/opendil/frame.html`. Copy these assets again when you upgrade the package.

Host (`mode="host"`) and Shadow DOM (`mode="shadow"`) modes do not require `copy-assets`. Their runtime code and workers are bundled with your application.

## Render a document

```tsx title="Answer.tsx"
import { DilRenderer } from "@snackbit/opendil";
import "@snackbit/opendil/styles.css";

export function Answer() {
  return <DilRenderer text="<title>Hello, interface.</title>" />;
}
```

## Send a stream

```tsx
<DilRenderer
  key={messageId}
  text={sourceReceivedSoFar}
  isStreaming={receiving}
/>
```

Append to the existing source prefix. Set `isStreaming={false}` after the final chunk. Use a new `key` to replace, edit, or restart a document. The renderer does not connect to a model provider or own your network transport.

Read [Streaming](../streaming/) for reveal, update cadence, and scroll following.

## Configure asset paths

`runtimeBaseUrl` applies only to iframe mode. For an application hosted below a subpath, point to the matching runtime directory:

```tsx
<DilRenderer text={source} runtimeBaseUrl="/my-app/opendil/" />
```

Keep the runtime assets and npm package on the same version. See [Isolation](../isolation/) for Shadow DOM and host rendering, and [Customization](../customization/overview/) for your own components and theme.
